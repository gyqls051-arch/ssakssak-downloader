# 자동 유지보수와 앱 업데이트

싹싹김치 다운로더 1.11부터 적용하는 배포 계약입니다. 1.10 이전 버전은 이 전환 설치 파일을 한 번 직접 설치해야 합니다. Windows Authenticode 인증서 대신 앱 내부에 고정한 Ed25519 공개키가 업데이트 권한을 검증합니다. Windows의 게시자 인증/SmartScreen 평판과는 별개입니다.

- GitHub 기본 브랜치의 maintenance.yml이 하루 두 번 안정판 yt-dlp를 확인합니다. 실제 소스는 기존 codex/family-freeware-hardening-20261023 브랜치를 사용합니다.
- 새 버전만 정확한 wheel SHA256으로 고정합니다. 필수 의존성이 새로 생기면 자동 승격을 중단합니다. 검사 실패도 공개/채널 갱신을 막습니다.
- 빌드 작업에는 서명키를 전달하지 않습니다. 분리된 서명 작업에서 검사한 Setup bytes에 대한 버전·크기·SHA256·출처 commit·유효기간을 서명합니다.
- 별도 Windows runner에서 실제 구버전 설치 → helper 소유권 확인 → 새 Setup 적용 → 새 프로그램 시작 검사 → 재실행을 확인해야 공개합니다.
- 앱은 시작 직후와 12시간 간격으로 채널을 확인해 새 버전이 있으면 '업데이트 해야합니다' 팝업과 상단 배너를 띄우고, 사용자가 업데이트를 선택하면 진행 중인 다운로드·분석이 없을 때 새 작업 진입을 잠그고 적용합니다. 실제 파일은 다시 해시/서명을 확인하고 쓰기/삭제 잠금을 잡아 실행합니다.
- 다운로드/검증 실패는 현재 앱을 종료시키지 않습니다. 설치/새 버전 시작 검사 실패는 백업한 앱·runtime·고지를 복원하고 기존 앱을 다시 실행합니다. 실패 버전은 다시 자동 설치하지 않습니다. 복구 시 Windows 제거 프로그램의 버전 표시 등 installer registry 메타데이터까지 되돌리는 것은 보장하지 않습니다.
- 원격 서명 manifest는 7일간 유효합니다. 새 엔진이 없어도 CI가 정기적으로 서명을 갱신합니다. 동시 workflow는 직렬화하며, 이미 공개된 설치 파일은 덮어쓰지 않습니다.

운영 개입은 upstream 호환성 결함, 검사 실패, GitHub 권한/장애, 서명키 복구/교체 등이 필요할 때 발생합니다. 실패 기록은 GitHub Actions와 로컬 앱 로그/updates/publisher/state.json에 남습니다. 합성 공개 fixture의 실제 다운로드/디코딩 검사는 모든 사이트의 지원·성공률을 보증하지 않습니다.

서명키는 GitHub Secret PUBLISHER_UPDATE_KEY로 관리합니다. 개인키를 저장소·artifact·로그에 넣지 마세요. 최초 설정한 Windows 계정에는 DPAPI로 암호화한 복구본을 별도 로컬 운영 폴더에 보관합니다. 이 복구본은 같은 Windows 계정에서만 복호화할 수 있습니다. 키가 노출됐거나 복구 불가한 경우 자동 배포를 중단하고 새 신뢰키를 포함한 전환 버전을 직접 배포해야 합니다.
