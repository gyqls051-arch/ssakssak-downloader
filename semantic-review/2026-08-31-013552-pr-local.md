# v1.9 상업 배포 게이트와 런타임 신뢰 경계 강화

이 변경은 다운로드 결과 확정, pywebview 입력 경계, 앱·엔진·ffmpeg 업데이트, 설정·종료 수명주기와 Windows 서명 릴리스를 함께 강화한다. Setup 검증과 릴리스 게이트는 엄격해졌지만, 상업 배포 전에 막아야 할 P1 여섯 건이 설정 일관성, 취소 확정, private-network egress, 업데이트 메타데이터, 런타임 코드 공급망, side-bundle 도구 고정에 남아 있다. 인증서·법적 값·Windows release lock 부재로 게이트가 닫히는 것은 의도된 fail-closed이므로 이슈에서 제외했다.

Watch for: **[P1 · confirmed]** 저장 실패 뒤 UI와 backend 쿠키 권한이 갈라지는 문제, **[P1 · confirmed]** 취소 후에도 harvest가 파일과 완료 콜백을 확정하는 문제, **[P1 · likely]** yt-dlp/WebView 하위 요청이 private-network 검사를 우회하는 문제, **[P1 · confirmed]** unsigned `version.json`이 강제 업데이트 UI와 임의 브라우저 fallback을 제어하는 문제, **[P1 · confirmed]** yt-dlp/ffmpeg가 게시자 서명과 독립된 신뢰 근거 없이 실행되는 문제, **[P1 · confirmed]** 검증한 Node와 별개인 PATH의 npm/node로 side bundle을 만드는 문제.

**Verdict**: NEEDS_CHANGES

## High-level view

다운로드 결과는 묶음 단위로 옮기도록 바뀌었지만, **[P1 · confirmed]** harvest 중에는 취소를 관찰하지 않아 사용자가 취소·종료를 먼저 요청해도 최종 파일과 성공 콜백이 뒤늦게 확정된다. rollback은 이동 실패만 다루며 취소 경합은 다루지 않는다.

설정 저장은 atomic replace를 사용하지만 메모리 설정을 먼저 변경하므로, **[P1 · confirmed]** 디스크 쓰기 실패 뒤 UI와 backend 권한이 달라질 수 있다. 특히 쿠키 opt-in은 실패 응답으로 UI가 OFF가 된 상태에서도 backend가 브라우저 쿠키를 읽도록 남는다.

DOM 텍스트 렌더링과 Python→JS JSON 경계로 좁힌 UI 입력면과 달리, **[P1 · likely]** public-only 네트워크 정책은 최초 URL 검사 뒤 yt-dlp와 WebView transport에 이어지지 않는다. redirect, extractor 요청, child manifest·segment, thumbnail redirect가 같은 private-address 정책을 적용받지 않는다.

Setup 자체는 hash·host·final URL·Authenticode signer·ProductVersion으로 묶였지만, 그 앞단의 **[P1 · confirmed]** unsigned `version.json`은 닫을 수 없는 업데이트 상태와 외부 링크를 결정한다. 별도 런타임인 yt-dlp와 ffmpeg도 **[P1 · confirmed]** mutable 배포 채널이 함께 제공한 payload와 digest만 신뢰해 signed app 경계 밖의 코드를 교체·실행한다.

Windows 릴리스 게이트가 canonical 단일 Setup과 서명 산출물을 검증하더라도, **[P1 · confirmed]** side bundle은 검증한 Node archive의 `node.exe`가 아니라 PATH의 미고정 `npm`과 그 npm이 선택한 node로 생성된다. clean-machine 전제와 실제 Git/npm 의존성도 README·build preflight에 반영되지 않았다.

### 취소 뒤에도 성공으로 확정되는 harvest

심각도는 **P1**, 신뢰도는 **confirmed**다. `main.py`의 `Downloader._harvest`, `Downloader._run_inner`, `Api._shutdown` 경로는 결과 이동 중과 완료 콜백 직전에 취소 상태를 확인하지 않는다. 큰 파일 또는 플레이리스트의 `shutil.move` 중 취소하거나 종료하면 `_cancel_event`가 set된 뒤에도 최종 폴더 커밋, `_on_item_done`, `_on_done(True, None)`이 이어진다. 최소 재현에서도 `shutil.move` 진입 시 취소를 걸자 이벤트가 set된 상태로 `video.mp4`와 item 완료 콜백이 확정됐다. 종료는 8초 뒤 worker가 남아 있어도 창을 파괴하므로 같은 경합이 부분 결과로 남을 수 있다.

각 이동 전후와 콜백 직전에 취소 선형화 지점을 두고, 확정 전 취소라면 이번 harvest에서 옮긴 파일을 작업 폴더로 rollback한 뒤 `DownloadCancelled`로 종료해야 한다. 다른 volume으로 복사될 수 있는 결과는 목적지의 고유 `.part`에 복사·fsync한 뒤 rename하고, 모든 파일이 확정된 뒤 한 번만 성공을 게시해야 한다.

### 저장 실패 뒤에도 유지되는 쿠키 opt-in

심각도는 **P1**, 신뢰도는 **confirmed**다. `main.py`의 `Api._update_settings`는 `_cfg.update(patch)` 후 `Settings.save`를 호출하고 실패 시 메모리 값을 복구하지 않는다. 앱 데이터 디렉터리를 쓰기 불가능하게 만든 뒤 쿠키를 OFF에서 ON으로 바꾸면 API는 `ok: false`를 반환하고 `web_ui/index.html`은 체크박스를 OFF로 되돌리지만, `_cfg["cookie_opt_in"]`은 `True`로 남아 다음 로그인형 분석이 브라우저 쿠키 DB를 읽는다. 같은 회귀로 저장 폴더도 UI와 실제 다운로드 대상이 달라질 수 있다.

patch를 설정 사본에 적용해 저장한 뒤 성공한 사본만 `_cfg`에 반영해야 한다. 실패 응답에는 실제 유지된 값을 반환하고, 쿠키 권한은 영속화 성공 전까지 다른 요청에서 관찰할 수 없어야 한다.

### 최초 URL 뒤에서 사라지는 private-network 차단

심각도는 **P1**, 신뢰도는 **likely**다. `main.py`의 `validate_public_http_url`, `VideoAnalyzer.probe`, `Downloader._run_inner`, `Downloader._download_manifest`는 최초 URL을 검사하지만 yt-dlp의 redirect·extractor API·HLS/DASH child manifest·segment 요청에는 같은 정책을 주입하지 않는다. `web_ui/index.html`의 `safeImageUrl`도 HTTPS 문법만 확인해 public thumbnail의 private-address redirect를 WebView가 그대로 따라갈 수 있다.

public endpoint가 `127.0.0.1`로 302를 반환하거나 public HLS manifest가 private segment를 가리키면 최초 DNS 검사는 통과하고 후속 요청은 별도 transport에서 수행된다. pywebview/yt-dlp가 없는 로컬 환경에서 종단 재현은 못 했지만, 생성 옵션과 이미지 경로에 per-request/redirect guard가 없는 것이 확인돼 우회 가능성은 높다. 이 때문에 `docs/PRIVACY.md`의 “public HTTP(S) 목적지만 허용” 설명도 실제 보장보다 강하다.

모든 outbound URL과 redirect를 yt-dlp RequestDirector/transport에서 socket 연결 전에 검증하고, 검증한 DNS 결과를 연결 대상에 고정해야 한다. child manifest·segment·extractor API에도 같은 정책을 적용하고, thumbnail은 backend가 동일 정책으로 가져와 로컬 리소스로 전달하거나 해당 경계가 생길 때까지 표시하지 않아야 한다.

### unsigned version.json이 제어하는 강제 업데이트 경로

심각도는 **P1**, 신뢰도는 **confirmed**다. `main.py`의 `UpdateChecker._interpret`, `Api._kill_and_update`와 `web_ui/index.html`의 `updateAvailable`/`appUpdate`는 unsigned JSON의 `min_supported_version`으로 닫을 수 없는 업데이트 상태를 만들고, signed Setup 자동 조회가 실패하면 원격 `download_url`을 브라우저 fallback으로 제시한다. 공격자가 더 큰 최소 버전, 존재하지 않는 최신 버전, 임의 public HTTP(S) URL을 게시하면 앱은 사용자를 그 링크로 유도한다. 자동 설치는 Authenticode에서 차단되지만 이 수동 경로는 서명된 Setup 경계 밖이다.

manifest에 독립 서명이 생기기 전에는 `min_supported_version`으로 강제 UI를 만들지 말고 항상 닫을 수 있어야 한다. fallback은 원격 값을 사용하지 말고 `GITHUB_RELEASE_REPO`에서 로컬로 구성한 exact HTTPS release URL로 제한하며, 강제 업데이트나 installer override를 쓰려면 manifest 전체의 publisher signature를 먼저 검증해야 한다.

### signed app 밖에서 교체·실행되는 yt-dlp와 ffmpeg

심각도는 **P1**, 신뢰도는 **confirmed**다. `main.py`의 `EngineUpdater._latest_from_pypi`/`_install`은 PyPI가 제공한 wheel과 digest를 함께 신뢰하고 다음 실행에 import한다. `FfmpegInstaller`는 비어 있는 `EXPECTED_SHA256`/`EXPECTED_SIZE` 대신 BtbN의 mutable `latest` API가 제공한 payload와 digest를 함께 신뢰하고, 추출한 EXE를 Authenticode 검증 없이 `_smoke_test`에서 즉시 실행한다.

PyPI 프로젝트나 BtbN release 계정이 탈취돼 payload와 metadata가 함께 바뀌면 TLS와 digest는 이를 탐지하지 못한다. wheel은 signed app 프로세스에 import되고 ffmpeg는 설치 중 실행되므로 Setup signer pin을 우회하며, release lock에서 검토한 yt-dlp도 첫 실행 후 미검토 최신판으로 교체될 수 있다.

앱 게시자가 서명한 update manifest에 허용 버전·size·SHA-256·exact URL을 넣고 그 값만 적용해야 한다. ffmpeg에 신뢰할 Authenticode signer가 없다면 검토한 hash/size를 signed app 또는 signed manifest에 pin하고 release gate에서 빈 pin을 거부해야 한다.

### 검증한 Node를 사용하지 않는 side-bundle 빌드

심각도는 **P1**, 신뢰도는 **confirmed**다. `prepare_bundle.py`의 `fetch_node`는 검증한 Node archive에서 `node.exe`와 license만 추출하지만, `build_server`는 PATH의 `npm.cmd`로 `npm ci`와 `npm prune`을 실행한다. README와 `build_installer.bat`에 적힌 도구만 있는 clean machine에서는 Git/npm 부재로 실패하고, npm이 있으면 미고정 전역 npm/node와 설정이 lifecycle script와 산출물을 결정한다. Node ZIP digest, bgutil tag commit, 고정 commit의 npm lock integrity는 공식 원본과 일치하므로 결함은 lock 내용이 아니라 이를 처리하는 toolchain 경로다.

검증한 archive에서 build 전용 npm CLI까지 임시 toolchain으로 추출하고 해당 `node.exe`로 `npm-cli.js ci`와 `prune --omit=dev`를 직접 실행해야 한다. npm 버전을 lock과 release gate에 포함하고, Git을 유지한다면 README와 preflight에 명시하거나 고정 commit source archive를 별도 SHA-256 pin으로 받아 의존성을 제거해야 한다.
